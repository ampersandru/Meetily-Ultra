# Meetily Ultra releases

Ultra's default branch is `codex/meetily-ultra`. PR38's original `codex/combined-audio-speakers-labs` branch remains unchanged. Ultra has bundle ID `com.ampersandru.meetily-ultra`, binary `meetily-ultra`, version 0.3.0, and separate macOS/fallback data directory `Meetily Ultra`. Portable Windows data stays beside Ultra's executable. Copyrights and model download origins are retained.

The editable vector logo is `frontend/public/ultra-mark.svg`; regenerate desktop icons with `cd frontend && pnpm exec tauri icon public/ultra-mark.svg --output src-tauri/icons`. Sidebar, About, app/window, tray, toast and installer branding use Ultra assets. The old upstream updater is not registered or queried. About and the tray direct users to Ultra's release downloads.

Use the manually dispatched **Release Meetily Ultra** workflow. It runs isolated frontend tests, production build and TypeScript checks, plus native Windows tests and macOS capture-worker/source-continuity tests. Each platform builds from the selected commit; publication requires every build and validation job to pass. The workflow checks checksums and publishes one initially drafted release only after all three installers exist. It refuses to overwrite an existing release version.

Windows: Visual Studio C++ Build Tools, Ninja, pinned LLVM 18 bootstrap, Rust 1.97.1+, Node 24 and pnpm 11.9.0. Run `./frontend/scripts/build-ultra-windows.ps1`. It builds the CPU helper and app, stages the hash-verified ONNX/DirectML runtime, checks Microsoft's Visual C++ redistributable signature, then bundles NSIS. Verification tests the archive and compares packaged application, sidecars and runtimes to the build outputs, followed by sidecar smoke tests.

macOS: run `bash frontend/scripts/build-ultra-macos.sh aarch64-apple-darwin` on Apple Silicon, or pass `x86_64-apple-darwin` on Intel. Install OpenSSL 3 headers, Xcode command-line tools and the same Rust/Node/pnpm versions. Native dependencies outside system frameworks are copied into the bundle and their install names rewritten before ad-hoc signing. This avoids relying on the builder's Homebrew libraries at runtime. The script checks signatures, architecture, permissions, bundled resources, sidecar behavior and DMG integrity. Builds require macOS 14.2 or later; Intel CI uses macOS 15 and Apple Silicon CI uses macOS 26, with Mach-O minimum OS checks enforcing the declared 14.2 floor.

Installers are not Windows Authenticode signed or Apple Developer ID notarized. No upstream signing secrets are copied. Automatic update artifacts/feeds are intentionally disabled for this initial release. Verification is build/package qualification, not a physical microphone/system-audio test, voice-match accuracy benchmark, or proof of capture quality on every computer. Model/audio-dependent ignored tests must be reported separately.

Cold-run follow-ups: LLVM is fetched from its public release URL with bounded retries/timeouts and the existing SHA-256 pin. After Mac native tests complete, only intermediate outputs inside the selected target/release directories are removed before APFS clone staging and DMG creation; source, app bundles and executables are preserved. This addresses hosted Intel runner disk exhaustion.

The separate NVIDIA build uses `build-ultra-windows.ps1 -Cuda`, CUDA 13.3, and SASS targets 75/80/86/89/120. Both Whisper and llama-helper compile with CUDA. Verification additionally compares all three shipped CUDA runtime DLLs before producing the distinct `windows-x64-cuda-setup.exe` asset. CPU and CUDA installers share Ultra identity/data; neither uses the upstream updater. The hosted workflow publishes the three baseline installers; the separately verified CUDA installer and its checksum are attached to the same release after its native build completes.

Windows packaging uses the current Microsoft v18 redistributable and checks both its Authenticode publisher and its version against `VCToolsVersion`. The extracted installer payload is checked again for that runtime floor. This includes CUDA builds made with Visual Studio 2026; using an older v17 redistributable is insufficient for those compiler versions.

The optional `reuse_intel_run` dispatch input reuses an already verified Intel artifact from the same owner-dispatched Ultra workflow. It validates the source workflow/branch/actor and requires identical application, native, icon, resource, lockfile and license inputs before downloading. Checksums, signatures, architectures, minimum OS, resources and sidecar smoke tests are repeated on the extracted app. This preserves prior native-test qualification when only release scripts/docs changed. Without the input, Intel is built and tested normally.

The Windows bootstrap now extracts only libclang/clang and resource headers from the official LLVM Windows installer, pinned to the Microsoft winget manifest checksum. It neither installs LLVM system-wide nor unpacks the full portable developer archive. The separate **Build verified Ultra Windows installer** workflow can qualify Windows packaging independently of Mac runner availability.

Mac CI caches Cargo downloads and the pinned ONNX prebuilt library cache, but not compiled target outputs. Its separate cache namespace prevents reusing absolute linker paths from another Xcode image (for example clang 17 runtime paths on the macOS 26 runner). Intel artifact reuse remains guarded by identical application inputs and repeated package checks.

Windows setup always invokes the bundled signed Microsoft redistributable rather than trusting the registry Installed flag; Microsoft handles upgrade/repair and a newer-installed result is accepted. Mac artifact source checks exclude the Windows-only NSIS directory, which is not part of a Mac payload. Both Windows installers are repackaged and verified after hook changes.

Headless GitHub Windows runs explicitly filter `audio::playback_monitor::tests::test_get_output_device`, which requires a physical default output endpoint. All other default tests run (422 passed, 13 opt-in ignored, one hardware test filtered when this suite is unchanged). Full workstation CPU and CUDA qualification each ran that hardware test and passed all 423 default tests with 13 opt-in tests ignored. No production audio behavior is changed by this CI-only selection.
